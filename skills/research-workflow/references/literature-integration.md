# Literature handoff and integration

Use before delegating a review/update and when integrating its return. Follow the host's literature routing and role-only tool boundaries; this guide does not authorize searches or new permissions. Reorganizing saved evidence needs no new search.

## Delegation packet

Announce delegation. Supply the bounded question, ranked essential/optional deliverables, constraints, existing review/catalog, absolute source paths and relevant project instructions. Children do not inherit the parent conversation. Let the reviewer choose useful children within configured limits; do not duplicate reviews or bypass dispatch caps.

For an update, explicitly pass this contract:

> Extend the current review in place. Reconcile retained evidence into its authoritative catalog, narrative and bibliography; preserve IDs, seed mappings, provenance, access/metadata limits and researcher notes. Refresh dependent views through the project workflow. Keep history non-destructively behind one current entry point. A separate review requires a distinct topic or explicit request.

Respect project-specific proposal-only/catalog-write restrictions: when integration is coordinator-owned, the reviewer returns proposed deltas rather than editing canonical records.

## Integrate and verify

- Reconcile the handoff with existing evidence; distinguish source statements, inferences, proposals and reused checks. Preserve disagreements and access limits.
- Verify affected IDs/counts, duplicate works, citations and links; refresh dependent catalog/narrative/bibliography views through the existing workflow.
- Check rendered navigation when a rendered site is affected. Record unperformed rendering or integration as partial; do not claim a successful child or tool call completes scientific verification.
- Retain researcher-owned notes, stable seed mappings and recoverable history. Avoid competing current reviews or parallel bibliographies.
- Report what was actually checked, unresolved evidence and decisions left to the researcher. New source acquisition, private uploads, Zotero writes and configuration changes require their own authorization.

If the reviewer is unavailable, suggest `/reload` or restarting with it enabled. On failure/budget exhaustion, expose the blocker and saved partial artifacts; ask before switching to an in-main review. Never claim an unrun delegation or bypass role-only tools through shell endpoints.
